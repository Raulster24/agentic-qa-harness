## Screens & navigation graph

| Screen | URL | Reached from | Auth |
| --- | --- | --- | --- |
| Landing | `/` → redirects to `/en/start` | entry point | public |
| Register | `/en/register` | Landing | public |
| Overview / Home | `/en/home` | after account creation or sign-in | authenticated |

Notes:
- Single-page app (Angular). `/` redirects to a locale-prefixed landing
  (`/en/...`). The locale prefix changes with the language switcher (`/de/...`).
- `/en/home` while signed out redirects back to `/en/start` (auth guard).
- **First-paint caveat**: the a11y tree immediately after navigation can be
  empty; wait for a known landing element before asserting. (Encoded in
  `LandingPage.waitForReady()`.)

## Clustered components (reused across screens → component objects)

| --- | --- | --- |
| App header / banner | every authenticated + public screen | `role=banner` |
| Footer language switcher | every public screen | `role=contentinfo` → `role=link` per language |
| Modal dialog | register, sign-in, error | `role=dialog` with an accessible name |

## Auth model

- **No username/password.** Identity is a 128-hex-char **security token**
  generated at account creation. Sign-in exchanges the token for a session.
- UI flows: create account (multi-step dialog) → token issued; sign-in dialog
  takes the token; invalid token → error dialog "Oops! Incorrect Security Token."

## API surface (observed in the network tab during the happy path)

> DISCOVERED — to be confirmed at the human gate. Drives the `set-up-via-API`
> auth fixture so journeys don't have to click through registration every time.

| Purpose | Method & path (observed) | Notes |
| --- | --- | --- |
| Create anonymous account | `POST /api/v1/user` | returns `{ accessToken }` (the security token) |
| Exchange token for session | `GET /api/v1/auth/anonymous/{token}` | returns `{ authToken }` (JWT bearer) |
| Session storage | `localStorage["auth-token"] = <JWT>` | how the SPA persists the session |
