## Exploration notes

Verified flows live on https://www.saucedemo.com.

Key observations / quirks:
- Login page is at '/'. Successful login goes to '/inventory.html'.
- Username/Password inputs expose placeholders 'Username'/'Password' (used via getByPlaceholder). They also carry data-test='username'/'password'. The login button has accessible name 'Login' (data-test='login-button').
- The cart badge is only rendered when the cart is non-empty. It has no distinct accessible role/name, so I used the CSS locator [data-test="shopping-cart-badge"] (commented in the spec). Observed value '1' after adding one product.
- Each product card is [data-test="inventory-item"]; I scope the 'Add to cart' button to the Sauce Labs Backpack card because every card has an identically-named button. After adding, the same card's button becomes 'Remove'.
- IMPORTANT QUIRK: Sauce Demo persists cart state across sessions (cookies/localStorage). During exploration the Backpack stayed in the cart between separate logins. The AC3 test first asserts the badge has count 0 after a fresh login; if the test runner reuses a storage state with a pre-populated cart this assertion could fail. The default Playwright config uses a clean context per test, so this is fine as written, but reviewers should avoid configuring a shared storageState that includes cart contents.
- Locked-out error text observed exactly: 'Epic sadface: Sorry, this user has been locked out.'
- No SPA empty-snapshot issues encountered; pages rendered synchronously after click. Web-first assertions handle any minor timing.
