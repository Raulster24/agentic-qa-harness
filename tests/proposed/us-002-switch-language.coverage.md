## Exploration notes

Observations:
- App is an Angular SPA. After page.goto, the first accessibility snapshot was empty; the spec relies on web-first assertions (expect(...).toBeVisible) which auto-wait, so no manual timeouts are needed.
- '/' redirects to the locale landing page at /<locale>/start (e.g. /en/start). I matched URL with regex /\/en(\/|$)/ to stay robust to the trailing path.
- The language switcher is in the footer (contentinfo landmark), rendered as plain anchor links with hrefs like '../de' and '../en'. I scoped locators to getByRole('contentinfo') to avoid ambiguity, though 'Deutsch'/'English' link names are unique on the page.
- Note the footer also contains a 'Chinese (简体中文)' link; 'English' and 'Deutsch' are exact distinct names and do not collide.
- Default language depends on browser/Accept-Language. In this environment '/' resolved to English. If the test environment sets a different Accept-Language, AC1 could be affected; the deployed config here defaulted to English as required.
- Verified the full round trip manually: en -> de -> en, all transitions re-render the interface text correctly.
